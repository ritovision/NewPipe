## Final adjudication — implementation decision

All **nine** findings are retained, with their original confidence levels and without claiming Claude performed runtime reproductions. **Three (001–003) are mandatory release blockers.** For the first ordinary-use release, the implementing recommendation is to resolve **all nine**: six others are either inexpensive direct contract corrections, observable reliability/capacity defects, or provider-risk cases that require targeted disproof. This is a stricter quality gate than the independent review's *three formally blocking* classification; it does not relabel Low issues as data-corruption defects. No fundamental rearchitecture or reversal of the Astra corrections is justified.

### Precise dispositions

- **001 — Confirmed source defect, P0, blocking.** A validly authorized but malicious/buggy client can submit globally duplicate changes in separate chunks. An expected UNIQUE failure then bypasses the sole known CHECK-rollback classification, leaving CONTROL permanently held. **Fix preconditions inside the committing SQL guard**; never weaken uncertainty tickets or clear them automatically. Consider user-influenced unique/FK/NOT NULL constraints in adjacent routes. Test a real full-migration Miniflare production-router path, including ticket/hold settlement and HELD close.
- **002 — Confirmed ordering defect, P0, blocking.** The actual `beforeRestore()` persists unpaired AI state before the native import's final `admit()`. Queue mutations are a suggested trigger, not a verified one; expiry and generation/local invalidation remain relevant. Split reversible AI command-admission quiescence/drain from irreversible unpairing **without holding a Room or tag lock while waiting for the drain**. On refusal restore active AI service admission/pairing exactly; on committed native replacement retain intentional unpair/restart. Exercise real paired-state and refusal tests.
- **003 — Confirmed source liveness defect, P0, blocking.** A frozen current-generation outbox is always re-sent before conflict decision, even after a definite rejected `start`. On exact definitive pre-commit refusals, reconcile/retire the *same sequence/digest* and examine the returned receipt before clearing. A racing COMMITTED receipt is not a RETIRED receipt. Transient network/timeout or unknown write responses **must not** trigger discard. Test head race, stage expiry, replay with server receipt and periodic post-restart behaviour.
- **004 — Confirmed workflow dead-end, P1.** Revoked/role-downgraded credentials plus durable pending identity prevent Forget and same-generation connection. Provide an explicitly confirmed **local detach-and-archive** and fresh-device re-enrollment path while retaining old receipts/journals for potential server reconciliation. Do not infer that arbitrary 401, replay mismatch or a read-only role proves every earlier operation was definitely refused. No cloud ticket may be cleared by the local UX.
- **005 — Confirmed overbroad event trigger, P1.** `streams` invalidation includes play/history/feed upserts and can schedule unnecessary capture/network work. The daily-cost and lock-latency estimates are **not measured**. Narrow to semantic catalog edits (and preserve tag changes through existing notifications), add dirty/fingerprint admission where appropriate, and measure baseline cost. Preserve periodic remote-change polling and actual saved-video/membership triggers.
- **006 — Provider-dependent risk, P1.** A successful abort followed by a known SQL allowance refusal can be repeated against the same multipart ID; Miniflare's success does not establish live R2 idempotence; this is a conditional failure scenario, not a reproduced provider incident. Inject repeat-abort provider failure; if the final state is quarantined, persist definite abort progress in the allowed, guarded envelope or restructure steps. Arbitrary failure does not prove abort succeeded, and merely suppressing R2 errors would be unsafe. Require a separately authorized isolated live check before relying on provider-specific behaviour.
- **007 — High-confidence, not yet reproduced, P1.** Ordinary `/recovery/abort` and `/recovery/abandon` from ROTATING differ from the eight tested replacement endpoints. Reproduce with production router and three-slot rotation, then make same-identity cleanup bounded and resumable with truthful UI state; never raise the 32-statement cap or silently replace an already approved rotation. Preserve both survivor archives.
- **008 — Direct product-contract mismatch, P2.** Replacement's documented toggle is *not changed merely by replacing cloud*. Preparing/cancelling a preview must not silently disable an already-enabled sync mode. Bring the controller and UI into agreement with the owner-approved spec using a generation-aware, final-confirmation admission; only change post-confirmation mode when explicitly required/approved. Keep cloud-recovery ZIP restore and ordinary one-time local restore's explicitly OFF semantics distinct. Do **not** amend the product spec simply to rationalize current code.
- **009 — Confirmed local storage lifecycle gap, P2.** Durable import/export staging avoids OS cache eviction but orphans `tag-import-*` and, after the export-integrity correction, `tag-export-*` on process death. Delete **only proven orphan temporary dirs** at the safe cold-start/init boundary, under ownership coordination, without removing a currently staged operation, swap journal, before-last-restore safety copy, pending cloud transfer, R2 archive, shared Gradle cache or any unrelated project's files. Test actual process kill and startup cleanup with interrupted native restore/swap cases.
