## Android — Claude and Astra findings

1. **Untrusted source discovery, playback and cookies:** accept. AI network/playback first checks official supported provider domains or exact locally configured PeerTube hosts. Unconfigured/custom-domain origins are refused before discovery, and saved references face the same check before remote play/append. The AI extractor never forwards upstream unscoped recaptcha cookies; restricted YouTube preference cookies are host-scoped. Public DNS/peer/body limits remain. This narrows AI URL/playback host support; it does not change manual NewPipe playback or catalog organization of saved rows. A configured PeerTube host is a user trust decision, not a promise that a compromised provider is harmless.
2. **Malformed request disabling connectivity:** accept. Per-command failures produce correlated rejection where session identity can be established. Bad frames cause transient reconnect, not persistent disable. Long display names are bounded/normalized and future unknown scopes are ignored, never granted. Permanent disable requires lost local key or explicit authenticated device revocation.
3. **Stop/policy publication and restore race:** accept. AiPolicyGate atomically orders invalidation/enqueue/publication; ordered Stop/revoke intents are persisted even if a later configuration is queued. Only a current version can publish enabled policy. Restore enters process-wide maintenance, immediately cancels remote/network access, fully disables the grant gate and drains the command lane including Library initialization before replacement begins. Setup is blocked until restart; even cancelled/failed import may require restarting AI setup. Native multi-file import is still not claimed crash-atomic.
4. **Old transport failure stopping new gate:** accept. A closed transport immediately fails only its own session predicates. Shared-gate invalidation is serialized and rechecks transport identity. Snapshot device/epoch/owner/origin/key/permissions must match the current relay.
5. **Bound-only playback and start failure:** accept. A bound service without a player receives a genuine Android service start; direct reuse only applies to an existing player. Dummy foreground fallback only handles actual Android starts. A partially created cold-start player is cleaned up on failure; the result stays UNKNOWN when effect cannot be ruled out.
6. **Foreground-start cancellation race:** accept. Runtime stopService only targets a service that completed startForeground. A pending start installs the notification before noticing disabled policy and stopping. A dedicated Pixel test exercises immediate cancellation and view recreation.
7. **Client admission:** accept. First-seen clients are serialized and durably recorded before execution; cap/storage failure rejects the command. Unknown clients cannot act without being visible and locally revocable.
8. **Blocked client reset:** accept. Same-owner re-pair and restore preserve explicit local blocks. Full Forget/reset explicitly says it resets blocks and credentials.
9. **Blocking/network resource leaks and PoToken handoff:** accept. Challenge/pairing requests register cancellable handles before dispatch; old generations cancel them. AI extraction owns a separate dispatcher/pool, cancels and evicts on completion/stop, and checks all response reads. Scoped PoToken waits are bounded/cancellable, network scope is captured before main-thread handoff and restored in Botguard IO, and cancelled unpublished WebViews are disposed. Ordinary non-AI waits retain upstream behavior. Explicit non-DIRECT proxy configurations are refused rather than silently bypassed; this limitation is documented. NAT64's public embedded IPv4 is permitted, private/6to4/Teredo cases are rejected.
10. **Notification visibility and panic:** accept. A dismiss action stops control, notification permission/channel visibility is checked, and panic has a short bounded drain then owned-key invalidation and exit. No guarantee is made that Android/OEMs always display an ongoing notification.
