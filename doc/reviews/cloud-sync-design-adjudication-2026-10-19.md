## Optional findings and nuances

- **Native allocation evidence: accept as a mandatory proof.** Preassign ordinary playlist IDs in the journal under the same writer/allocation barrier, using sqlite_sequence and current maximum with overflow checks; preserve the incarnation. AUTOINCREMENT is not sufficient across restore/manual explicit-ID insertion. No reuse of AI receipts for cloud authority. If this proof needs a narrow fork-owned receipt migration, adjudicate it rather than hiding it.
- **Cross-store UI visibility: accept correction.** Room observers can fire at Room commit. Promise an invariant-valid Room phase and fenced/recovered tag-dependent access, not impossible simultaneous multi-database observer notification.
- **Disable ordering: accept.** Persist mode/generation under the apply barrier. Previously admitted apply completes before that point; future apply is barred. Cancellation never undoes a request already committed remotely.
- **Equal local/cloud after independent changes: accept.** Resolve pending operation first, then adopt equal validated content as baseline rather than creating a needless conflict.
- **Sequence-only identity: accept.** Keep a transport/staging ID only when it identifies a distinct object; do not require an extra operation UUID for receipts.
- **All-multipart recovery: accept with race caveat.** One final part supports small archives; >=5 MiB/equal-sized nonfinal parts. Abort is not proof that a concurrent completion did not win; verify/clean the completed object before freeing its slot. ETag is not full-file SHA-256.
- **Snapshot + catch-up download: defer.** Bounded page revalidation/retry can report busy under sustained writes but cannot install mixed data. A read pin or retained snapshot plus journal catch-up is a liveness optimization for measured need, not a prerequisite to the first protocol proof. No R2 staging workaround.
- **Local recovery overwrite: accept.** Preserve an existing local safety point when the outgoing automatic-cloud state is already verified recoverable in R2; do not accumulate unlimited local snapshots.
- **Maps while disabled: accept.** One-time pull preserves portable/native mappings for later enablement, scoped by database incarnation.
- **Default preferences and triggers: accept.** Keep all cloud runtime state outside exported default preferences. Do not add SQL triggers: current backup schema validation rejects them. Native lifecycle hooks and durable baseline comparison must capture writes.
