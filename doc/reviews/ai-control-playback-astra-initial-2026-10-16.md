**BLOCK** — source-only review of all seven changed/new Kotlin files and the architecture document against `2b5108659`.

1. **P1: Interrupted waits leave executable callbacks and bindings behind.** [AiAndroidPlaybackPort.kt:109](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/custom/aicontrol/AiAndroidPlaybackPort.kt:109) has no `finally`: `InterruptedException` bypasses cancellation and unbinding. The executor returns `OUTCOME_UNKNOWN`, but a later connection can still execute the command. Timeout also does not cancel a callback that already passed the check at line 68. **Mitigation:** atomically distinguish pending, executing and cancelled work; always schedule cleanup on exit and preserve interruption.

2. **P1: The skip guard can validate the wrong queue occurrence.** [AiAndroidPlaybackPort.kt:168](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/custom/aicontrol/AiAndroidPlaybackPort.kt:168) combines `queue.index` with `player.currentItem`, which updates asynchronously through queue events. Removing current A from `[A,B,C]` can leave index 0 pointing to B while `currentItem` still identifies A; an outstanding `(0,A)` request then skips B. Even after synchronization, replacement/reordering can reuse the same index and URL. **Mitigation:** require a consistent selected-item snapshot and an opaque queue/occurrence revision, checked immediately before advancing.

3. **P2: Binding success is incorrectly used as a liveness result.** [AiAndroidPlaybackPort.kt:96](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/custom/aicontrol/AiAndroidPlaybackPort.kt:96) assumes an absent service produces `false`. With flags `0`, binding can return `true` without delivering a connection—explicitly documented in existing [PlayerHolder.java:214](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/player/helper/PlayerHolder.java:214). Consequently, an ordinary stopped player produces a timeout/unknown result instead of inactive state. The false-return path also never unbinds. **Mitigation:** separate binding registration from player availability, clean up unsuccessful binding attempts, and distinguish timeout before dispatch from uncertain execution.

4. **P2: Skip can report success without advancing.** [AiAndroidPlaybackPort.kt:167](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/custom/aicontrol/AiAndroidPlaybackPort.kt:167) checks only queue size. At the last loaded item of an incomplete queue, [PlayQueue.java:145](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/player/playqueue/PlayQueue.java:145) clamps the next index to the current index, yet the adapter returns `skipped=true`. **Mitigation:** establish that a next selection exists and verify the resulting transition; otherwise return an explicit unavailable/pending result.

5. **P2: Forgotten results become misleading `NOT_EXECUTED` replies.** [AiPlaybackExecutor.kt:57](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/custom/aicontrol/AiPlaybackExecutor.kt:57) removes history after 180 seconds, then checks expiry at line 68. Retrying a previously completed request after eviction returns `EXPIRED/NOT_EXECUTED`, although its original effect occurred. **Mitigation:** report unavailable historical outcomes as `OUTCOME_UNKNOWN`; expiry prevents new execution but does not establish the original outcome.

6. **P2: Argument-validation failures lose response correlation.** [AiPlaybackExecutor.kt:48](/home/rito/techstuff/ritoverse/newpipe-ai-control/app/src/main/java/org/schabi/newpipe/custom/aicontrol/AiPlaybackExecutor.kt:48) validates inside `decode()` before assigning `request`. A valid envelope containing an invalid skip index therefore returns empty request/device IDs. **Mitigation:** decode the envelope, retain its validated correlation IDs, then validate arguments, matching the catalog executor.
