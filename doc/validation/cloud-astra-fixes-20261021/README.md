## Additional coordinator finding: full native export staging integrity

While the independent reviewer worked on its frozen `582f0791d` source, a separate implementer probe found the analogous **export** boundary was still vulnerable: `export()` staged validated snapshots in cache and later used `Files.exists` to decide which ZIP entries to include. A test removed only the already validated tag snapshot when the output stream opened. The unmodified product returned success for the incomplete ZIP. The regression deliberately failed (**0/1 passed**) on that original implementation; `export-loss-before-fix.log` and artifact identities preserve the reproduction. This is a new coordinator-discovered export defect, not a claim that the already corrected import-inventory tests failed or that Claude performed a runtime reproduction.

The additional correction keeps authoritative export staging in private no-backup storage, freezes the exact entry inventory before opening the destination (Room/tag always required; binding optional only if originally absent), and verifies each file's size/hash while streaming its bytes into the ZIP. A missing or changed validated source cannot silently disappear from a successful full backup. The existing installed data, native writer/snapshot rules and failed-export behavior remain unchanged. A failed destination write may leave an incomplete output file, which is explicitly not a valid completed backup; the local safety-copy coordinator never promotes that failed pending file over its prior recovery copy.

App/test builds and all **353 JVM tests passed** on this follow-up. **93 native backup/sync/recovery/replacement tests passed**, zero failures, 164.504 seconds, including the former failure, independent Room/tag/binding disappearance, same-length mutation and existing export/import/cloud-controller paths. These 93 overlap the earlier 191-test suite and are not additive. APK identities are in `export-integrity-apks.json`.
